# Alert 사용 규칙

`Alert`를 쓰거나 고칠 때 **이 문서대로 쓰는 것을 권장**합니다. 출처는 Figma `Alert Guidelines`(node `2199:2532`)와 `Alert`(node `2197:1017`)입니다. Figma와 이 문서가 다르면 Figma가 맞습니다.

- 사용자가 **꼭 확인하고 넘어가야 하는 상황**에 쓰는 대화상자입니다. **같은 일을 하는 버튼을 여러 개 두지 않습니다.**
- 클라이언트 컴포넌트(`"use client"`)입니다. **`useOverlay`로 여는 것을 권장합니다**: `overlay.open(({ isOpen, close }) => <Alert open={isOpen} onClose={close} … />)`. 앱 최상단에 `OverlayProvider`가 있어야 합니다.
- 반응형 웹(모바일웹 ~ PC)에서 같은 컴포넌트를 씁니다. 폭은 320(최소 280)이고, 좁은 화면에서는 좌우 여백 20을 지킵니다.

## 언제 쓰나요

**흐름을 멈추고 확인을 받을 때만** 씁니다. 정보만 알리는 일에는 Alert를 쓰지 않고 Toast나 Snackbar를 씁니다.

|      | Alert                         | Toast              | Snackbar             |
| ---- | ----------------------------- | ------------------ | -------------------- |
| 목적 | 꼭 확인해야 하는 일           | 결과를 짧게 알려요 | 다음 행동을 제안해요 |
| 흐름 | 화면을 멈추고 응답을 기다려요 | 자동으로 사라져요  | 자동으로 사라져요    |
| 버튼 | 버튼 1~2개                    | 없어요             | 1개 (선택)           |

## 구성

종류와 버튼을 골라요.

| 구성            | 선택지 / 켜고 끄기            | 설명                                                      |
| --------------- | ----------------------------- | --------------------------------------------------------- |
| 제목(`heading`) | 켜고 끌 수 있어요 (생략 가능) | 한 줄로 상황을 요약해요                                   |
| 본문(`body`)    | 필수                          | 해결 방법을 적어요                                        |
| 버튼(`action`)  | `Button` 1~2개를 직접 넣어요  | 주된 행동 옆에 취소 같은 보조 행동을 둬요                 |
| 배경(Scrim)     | 항상 있어요                   | 화면을 어둡게 덮어서 Alert 뒤의 화면을 누르지 못하게 해요 |

- Figma의 종류(Variant)는 `Normal` · `Negative`입니다. **되돌릴 수 없거나 위험한 일은 Negative로 알립니다.** 코드에서는 `variant`가 없고, 주된 버튼을 `color="destructive"`로 두는 것으로 표현합니다.
- `heading`과 `body`는 `ReactNode`라서 줄바꿈이나 강조를 넣을 수 있지만, **버튼·입력창 같은 조작 요소는 넣지 않습니다.**
- 사용하는 쪽은 `<Alert ... />`처럼 **자식 없이** 씁니다(`heading`·`body`·`action`을 모두 props로 넘깁니다).

```tsx
<Alert
  open={open}
  onClose={() => setOpen(false)}
  heading="탈퇴할까요?"
  body="탈퇴하면 관심 코인과 알림 설정이 모두 사라져요."
  action={
    <>
      <Button color="secondary" onClick={() => setOpen(false)}>
        취소
      </Button>
      <Button color="destructive" onClick={() => setOpen(false)}>
        탈퇴
      </Button>
    </>
  }
/>
```

## 사용 규칙

버튼 이름은 **행동을 그대로** 씁니다.

| 구분 | 내용                                                                  |
| ---- | --------------------------------------------------------------------- |
| 권장 | 제목에 상황을, 본문에 해결 방법을 적어요                              |
| 권장 | 버튼은 `삭제`와 `취소`처럼 행동을 구체적으로 써요                     |
| 금지 | `확인`과 `확인했어요`처럼 **같은 일을 하는 버튼을 두 개** 두지 않아요 |
| 금지 | 정보만 알리는 일에 Alert를 쓰지 않아요. Toast나 Snackbar를 써요       |

- 버튼은 1~2개입니다. 취소 같은 보조 행동은 **앞**(`secondary`), 주된 행동은 **오른쪽 끝**에 둡니다.
- 닫는 것은 각 버튼의 `onClick`에서 `open`을 바꿔서 합니다. `onClose`는 <kbd>Esc</kbd>를 눌렀을 때 호출됩니다.

## 접근성

누구나 쓸 수 있도록 다음을 지켜 주세요.

- **키보드로 조작해요:** <kbd>Tab</kbd>으로 버튼을 옮기고 <kbd>Enter</kbd>로 실행하고 <kbd>Esc</kbd>로 닫아요.
- **포커스를 가둬요:** Alert가 열리면 포커스가 안으로 이동하고, 닫히면 원래 자리로 돌아가요. 브라우저의 모달 `<dialog>`(`showModal`)가 처리합니다.
- 뒤 화면은 눌러지지 않고 스크롤도 막힙니다.
- `role="alertdialog"`이고, 제목은 `aria-labelledby`, 본문은 `aria-describedby`로 연결됩니다. 제목을 생략해도 본문은 읽힙니다.

## Props 요약

`open`(필수) · `onClose` · `heading` · `body`(필수) · `action`(필수)와 나머지 `<dialog>` 속성. 자세한 표는 docs의 Alert 페이지를 봅니다.
