# Button 사용 규칙

`Button`을 쓰거나 고칠 때 **이 문서대로 쓰는 것을 권장**합니다. 출처는 Figma `Button Guidelines`(node `2194:12248`)와 `Button`(node `2194:12744`)입니다. Figma와 이 문서가 다르면 Figma가 맞습니다.

- 서버 컴포넌트에서 그대로 쓸 수 있습니다(`"use client"` 없음). `onClick`을 넘길 때만 클라이언트 컴포넌트 안에서 씁니다.
- 반응형 웹(모바일웹 ~ PC)에서 **같은 컴포넌트**를 쓰고, 화면 폭에 따라 바뀌는 것은 배치와 폭뿐입니다.

## 언제 쓰나요

- 버튼은 **사용자의 행동을 실행**합니다(완료, 제출, 다음, 삭제). 다른 화면으로 이동만 한다면 버튼 대신 **링크**를 씁니다.
- 필터나 옵션 선택(전체, 시그널, 에어드랍)처럼 정보를 보여 주고 고르는 용도는 버튼이 아니라 **Chip**입니다.
- 버튼은 단독으로 쓸 수 있습니다. Chip은 보통 2개 이상 묶어서 씁니다.

## 위계: 종류 고르기

화면에서 버튼의 중요도에 따라 `variant`와 `color`를 고릅니다. **강한 버튼은 화면당 1개만** 씁니다.

| 위계 | 종류                                          | 화면당  | 쓰임새                                        |
| ---- | --------------------------------------------- | ------- | --------------------------------------------- |
| 강   | `solid` `primary` · `neutral` · `destructive` | 1개     | 가장 중요한 행동                              |
| 중   | `solid` `secondary`                           | 여러 개 | 대부분의 액션 버튼. CTA와 함께 쓰면 보조 행동 |
| 약   | `outline`(`neutral`·`primary`) · `ghost`      | 여러 개 | 낮은 위계의 보조 행동                         |

- `primary`는 핵심 기능에만 아껴 쓰고, **일반 화면의 CTA는 `solid neutral`** 을 씁니다.
- `destructive`는 삭제처럼 **되돌리기 어려운 행동**에만 씁니다. 색뿐 아니라 `삭제`처럼 **글자로도** 의미를 전합니다.
- `outline`은 같은 위계끼리 짝지어 쓰고 **`solid`와 섞지 않습니다.**

```tsx
<Button color="neutral">다음</Button>
<Button color="destructive">삭제</Button>
<Button color="secondary">닫기</Button>
<Button variant="outline">공유</Button>
<Button variant="ghost">더보기</Button>
```

## 크기

4단계 크기를 모바일웹과 PC에서 똑같이 씁니다.

| `size` | 높이 · 좌우 패딩 | 모서리 | 글자           | 쓰임새                                        |
| ------ | ---------------- | ------ | -------------- | --------------------------------------------- |
| `lg`   | 48 · 20          | 12     | Label 1 Medium | 모바일 하단 고정, 주요 CTA                    |
| `md`   | 40 · 16          | 12     | Label 2 Medium | 카드, 폼, 모달 (기본)                         |
| `sm`   | 32 · 12          | 12     | Label 3 Medium | 표, 목록, 필터                                |
| `xs`   | 28 · 8           | 8      | Label 3 Medium | 표 안 버튼, 촘촘한 목록. PC 위주, 아이콘 없음 |

- **색(2026-11-12 Figma 갱신)**: 글자는 모든 크기에서 Medium. `outline`은 흰 배경(`fill-white`, 비활성도 흰 배경 + `border-disabled`), `ghost` 글자는 `text-secondary`. `solid neutral`은 `fill-neutral`(gray-800), 누름·로딩은 `fill-neutral-pressed`(gray-700), `destructive`는 `fill-danger`(red-400).

- 모바일 터치 영역은 44px 이상이어야 합니다. `sm`과 `xs`는 보이는 크기는 그대로 두고 눌림 영역만 44px로 넓어집니다(터치 화면에서 자동).
- `xs`는 **모바일에서 되도록 쓰지 않습니다.**

## 조합: 버튼을 나란히 둘 때

3개 이상 나란히 두면 시각적 무게가 같아져 혼란스럽고, 큰 글자 설정에서 레이블이 잘릴 수 있습니다.

```tsx
// 권장: 닫기 + 확인은 3:7 폭 비율. 해제 동작은 secondary, 확인은 solid
<div style={{ display: "flex", gap: 8 }}>
  <div style={{ flex: 3 }}><Button color="secondary" size="lg" fullWidth>닫기</Button></div>
  <div style={{ flex: 7 }}><Button size="lg" fullWidth>참여하기</Button></div>
</div>

// 권장: outline은 같은 위계끼리 반반
<Button variant="outline" fullWidth>공유</Button>
<Button variant="outline" fullWidth>저장</Button>
```

| 구분 | 예                       | 이유                                                           |
| ---- | ------------------------ | -------------------------------------------------------------- |
| 권장 | 닫기 + 확인 (3:7)        | 해제 동작은 `secondary`, 확인은 `solid`                        |
| 권장 | `outline`끼리 짝         | 같은 위계끼리 반반                                             |
| 금지 | `solid`와 `outline` 혼용 | 위계가 섞여 어떤 행동이 중요한지 헷갈립니다                    |
| 금지 | 3개 이상 나란히          | 선택이 어렵습니다. 추가 행동은 `IconButton`(더보기)으로 뺍니다 |

## 아이콘

아이콘은 레이블 읽기를 방해하지 않도록 **아껴 씁니다.** 앞(`leftAddon`) 또는 뒤(`rightAddon`) **중 하나만 쓰는 것을 권장**합니다. 둘 다 넣을 수는 있지만 레이블이 묻히므로 **지양**합니다.

```tsx
<Button leftAddon={<PlusIcon />}>추가</Button>            {/* 행동의 의미를 보조: 글쓰기 + 연필 */}
<Button rightAddon={<ArrowRightIcon />}>더 보기</Button>  {/* 동작의 방향·결과: 다음 + 화살표 */}
```

- `xs`는 아이콘이 없습니다(넘겨도 그리지 않습니다).
- **아이콘만 필요하면 `Button`이 아니라 `IconButton`** 을 씁니다. 의미 전달이 약하므로 꼭 필요한 곳에만 쓰고 이름(`aria-label`)을 붙입니다.

## 상태

| 상태            | 설명                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------ |
| Normal          | 기본 상태                                                                                                          |
| Disabled        | 누를 수 없는 상태. **이유가 필요하면 주변에 안내 문구**를 둡니다                                                   |
| Loading         | `loading`. hover·pressed 색과 진행 원만 보여 줍니다. 레이블은 숨기고 **크기는 그대로** 유지하며 중복 탭을 막습니다 |
| Hover · Pressed | **같은 색**이라 모바일웹(터치)과 PC가 같은 피드백을 줍니다. 색은 조합마다 정해져 있습니다                          |
| Focused         | 키보드로 이동했을 때 포커스 링(1px). 버튼마다 따로 만들지 않고 공통 포커스 규칙(`focus-visible`)으로 처리합니다    |

## 반응형

같은 버튼을 모바일웹과 PC에서 쓰고 **화면 폭에 따라 배치만** 바꿉니다.

- **모바일**: `lg` 버튼을 **가로 가득**(`fullWidth`)으로 두고 좌우 여백 20, 아래에는 브라우저 하단과 safe area 여백을 포함합니다. 하단에 고정합니다.
- **태블릿 이상**: **내용 폭**(기본값)으로 두고 최소 너비 64입니다. 폼과 모달 하단 버튼은 **오른쪽 정렬**하고 사이 간격은 8입니다.
- 버튼 사이 간격은 가로 8, 세로 8입니다.
- **레이블은 한 줄**입니다. 넘쳐도 말줄임(`...`)을 쓰지 않고, 번역이나 큰 글자 설정으로 한 줄에 안 들어가면 **가로 배치를 세로 배치**(주요 행동이 위)로 바꿉니다.
- 화면 폭에 따른 분기는 CSS 접두어(`tablet:`, `desktop:`)로만 합니다. `useMediaQuery`로 나누지 않습니다.
- **`size`·`fullWidth`는 구간별 값을 받습니다.** 값 하나면 모든 화면에서 같고, 객체면 구간마다 달라집니다(`base` 모바일 · `tablet` 768px~ · `desktop` 1024px~, 빈 구간은 앞 구간 값을 이어받고 `base`를 빼면 기본값). 위 모바일·태블릿 배치는 이렇게 씁니다.

```tsx
<Button
  size={{ base: "lg", tablet: "md" }}
  fullWidth={{ base: true, tablet: false }}
>
  참여하기
</Button>
```

- 색·위계(`variant`·`color`)는 구간별 값을 받지 않습니다. 화면 폭에 따라 위계가 바뀌면 사용자가 헷갈립니다.

## 레이블

사용자 입장에서 쓰는 **짧은 동사형** 문구를 쓰고, 같은 행동은 서비스 전체에서 같은 문구를 씁니다.

- 권장: `참여하기`, `저장`, `알림 받기`, `관심 코인 추가`처럼 행동이 분명한 동사형. 레이블만 읽어도 누르면 무슨 일이 생기는지 알 수 있게. 2~6자 안팎으로 짧게. 같은 행동은 같은 문구(저장/보관을 섞어 쓰지 않기).
- 금지: `클릭`, `확인하시겠습니까?`처럼 행동이 불분명한 문구 / `여기를 눌러 참여하세요!`처럼 군더더기가 많은 문구 / `제출 처리`처럼 시스템 입장의 표현 / 아이콘 없이 `…`만 쓰는 버튼.

## 접근성

- 글자 대비 4.5:1 이상(비활성 제외). 흰 글자 on blue-600은 기준을 충족합니다.
- 키보드 포커스 링은 항상 보이게 합니다.
- `destructive`는 색뿐 아니라 글자로도 의미를 전합니다.
- 터치 영역 44px 이상(`sm`·`xs`는 눌림 영역 확장).
- `loading` 중에는 클릭을 막고(`aria-busy`), **"처리 중" 상태를 보조기기에 알립니다.**
- 아이콘만 쓰는 버튼(`IconButton`)에는 `aria-label`을 붙입니다.

## Props 요약

`variant` · `color` · `size` · `leftAddon` · `rightAddon` · `loading` · `disabled` · `fullWidth`와 나머지 `<button>` 속성. 자세한 표는 docs의 Button 페이지를 봅니다.
