# 내비게이션

> 색인: [`../AGENTS.md`](../AGENTS.md)

- **`Header`** — 서비스 맨 위에 고정되는 글로벌 내비게이션(Figma `Header Desktop`·`Header Mobile`). 어두운 알약 하나에 로고 · 메뉴 · 오른쪽 영역(로그인 버튼 또는 프로필)이 있고, **768px부터 메뉴를 펼치고 그보다 좁으면 햄버거로 접습니다**(CSS만 쓰므로 화면 폭을 읽는 코드가 필요 없습니다. Desktop과 Mobile을 따로 import하거나 같이 쓰지 않습니다). 클라이언트 컴포넌트입니다(`"use client"`가 달려 있어 서버 컴포넌트에서 import해도 됩니다. 단 함수 props(`onLoginClick`·`onMenuClick`·`profile.onClick`)는 클라이언트 컴포넌트에서 넘깁니다). 상세 규칙은 `components/header/AGENTS.md`
  - **라우팅**: 로고·메뉴·로그인·프로필·햄버거의 링크는 모두 `linkComponent`로 그립니다. Next.js는 `linkComponent={Link}`(`next/link`), 생략하면 `<a>`입니다. 다른 라우터의 Link도 `href`·`className`·`onClick`·`children`을 받으면 됩니다. core는 `next/*`를 import하지 않습니다
  - **현재 위치**: `items[].active`를 사용하는 쪽이 라우터에서 계산해 넘깁니다(Next.js는 `usePathname()`이라 `Header`를 쓰는 파일이 클라이언트 컴포넌트가 됩니다). `active`는 흰 글자 + `aria-current="page"`입니다. 나머지는 옅은 흰 글자
  - `logo`(필수, 높이 32 안): `<img>`·`<svg>`. 누르면 `logoHref`(기본 `/`)로 이동. 스크린리더 이름 `logoLabel`(기본 "홈")
  - `items`(필수): `{ label, href, active? }[]`. **6개까지**(한 줄에 맞게 디자인됨). 화면이 좁으면 숨겨지고 햄버거 뒤 메뉴 화면에서 보여 줍니다
  - `user`: `guest`(기본, 로그인 버튼) · `member`(프로필 Avatar 40). 로그인 버튼은 `loginLabel`(기본 "로그인")·`loginHref`(이동)·`onLoginClick`. 프로필은 `profile={{ src, name, badge, href, onClick }}`이고 `badge`가 알림 점입니다
  - 햄버거(768px 미만): `menuHref`(메뉴 화면으로 이동) 또는 `onMenuClick`. 이름 `menuLabel`(기본 "메뉴"). 메뉴 화면 자체는 Header 범위 밖입니다
  - `hideOnScroll`(기본 `true`): 스크롤을 내리면 가려지고 올리면 다시 보입니다(sticky, 위쪽 80px 안에서는 항상 보임, 키보드 포커스가 들어오면 보임). 항상 보이려면 `false`
  - 폭: 부모 폭을 채우고 최소 240px. 모바일은 알약이 Figma 375px 화면의 335px을 비율로 옮긴 폭의 89.3333%를 가운데에 쓰며(375px이면 335px, 로고 칸이 남는 폭을 차지), 768px부터는 내용 폭으로 가운데에 놓입니다
  - 바깥 여백은 태블릿 20·데스크톱 64이고 알약은 가운데입니다. 나머지 `<header>` 속성을 받습니다
  - 금지: 메뉴를 7개 이상 넣기, 현재 위치 메뉴를 여럿 `active`로 두기, `Header`를 페이지마다 따로 만들어 세우기(레이아웃에 한 번), 로고·메뉴를 `div`로 직접 조립하기

- **`Category`** — 같은 목록을 거르거나 분류를 고르는 칩 목록. 한 번에 하나만 선택하고, 넘치면 가로로 스크롤합니다(터치·트랙패드는 밀어서, 마우스는 끌어서. 끈 뒤에는 칩이 선택되지 않고, 놓으면 관성으로 조금 더 미끄러짐). 클라이언트 컴포넌트입니다(`"use client"`가 달려 있어 서버 컴포넌트에서 import해도 됩니다. 단 `onChange`는 클라이언트 컴포넌트에서 넘깁니다).
  - `items`(필수): `{ value, label, icon?, badge?, disabled? }[]`. 3~7개 권장. `icon`은 글자 앞 16px 아이콘, `badge`는 글자 오른쪽 위 빨간 점(새 소식)
  - `value`·`onChange`(제어) 또는 `defaultValue`(비제어). 항상 하나가 선택되어 있습니다
  - `all`: 맨 앞 "전체" 칩(기본 `true`, 값 `"all"` = `CATEGORY_ALL`, 처음 선택). 글자는 `allLabel`
  - `variant`: `solid`(흰 화면, 기본) · `outline`(회색 배경 위)
  - `size`: `lg`(40, 모바일웹 권장) · `md`(32, 기본, 촘촘한 영역. 터치 눌림 영역은 44). Figma Large·Medium, `Chip`과 같은 이름. 구간별 객체도 받음(`{ base: "lg", desktop: "md" }`)
  - `shape`: `square`(기본) · `pill`
  - `fade`: 넘칠 때 스크롤할 쪽 가장자리 그라데이션(기본 `true`, 자동으로 나타남)
  - `aria-label`을 꼭 줍니다(`radiogroup`의 이름). 키보드는 ←·→·Home·End로 선택
  - 금지: 두 줄 줄바꿈, 복수 선택(Checkbox를 씀), 화면 섹션 전환(Tab을 씀). 상세 규칙은 `components/category/AGENTS.md`
- **`Menu`** · **`MenuItem`** · **`MenuGroup`** · **`MenuDivider`** — 옵션이나 액션을 쌓아 보여 주는 목록 상자(Figma `Menu`). 열고 닫는 것·위치는 정하지 않습니다(떠 있게 하려면 `Popover`에 넣음: Popover는 `padding={0}`, Menu는 `className="w-full shadow-none"`). 클라이언트 컴포넌트입니다(`"use client"`가 달려 있어 서버 컴포넌트에서 import해도 됩니다. 단 `onChange`·`onClick`은 클라이언트 컴포넌트에서 넘깁니다). `Menu.Item`처럼 점으로 접근하지 말고 각각 import합니다.
  - `Menu`: 상자. `variant`: `normal`(고른 항목에 체크 표시, 기본) · `radio`(하나만, 앞에 원) · `checkbox`(여러 개, 앞에 상자). `aria-label`을 줍니다(`role="menu"`의 이름)
  - 값: `normal`·`radio`는 `value`·`onChange(value: string)`(제어) 또는 `defaultValue`(비제어). `checkbox`는 `string[]`이고 `onChange`가 고른 값 전체를 배열로 받습니다
  - `size`: `sm`(항목 36, 폭 200) · `md`(44, 240, 기본) · `lg`(52, 280). 폭은 `className="w-full"`로 늘립니다(최소 160). 구간별 객체는 받지 않습니다. 터치 화면에서 누르는 메뉴는 `md` 이상
  - `cellPadding`: `8`(촘촘한 목록, 기본) · `12`(일반 목록). `maxHeight`: 항목 영역의 최대 높이, 넘치면 그 안에서 스크롤(숫자는 px)
  - `actionArea`: 아래 52px 액션 줄(위에 선). 선택을 적용·초기화하는 버튼 둘을 `<Button variant="ghost" color="neutral" size="sm">`·`<Button size="sm">`로 넣습니다(양끝으로 벌어짐)
  - `MenuItem`: 항목 하나(`<button>` 전체가 눌림). `value`(고를 수 있는 항목. 생략하면 고르지 않고 `onClick`만 하는 액션), `children`(동사로 짧게), `leadingImage`(앞 24px 동그란 이미지 주소, 세 종류 모두), `disabled`. 일반 모양에서 선택된 항목은 굵은 글자 + 오른쪽 체크, Radio·Checkbox는 글자만 브랜드 색. hover·누름은 같은 색
  - `MenuGroup`(`label`): 항목을 이름 붙은 묶음으로 나눔. `MenuDivider`: 묶음 사이 가로선
  - 키보드: ↑·↓로 항목 이동(끝에서 반대쪽으로), Home·End로 처음·끝
  - 금지: Menu 안에 Menu를 겹쳐 펼치기, 값을 골라 입력하는 폼(Select를 씀), 5개 이상에서 하나만 고르기, 위험한 동작을 맨 위에 두기. 상세 규칙은 `components/menu/AGENTS.md`
- **`SegmentedControl`** — 같은 영역의 보기 방식(목록/격자, 일/주/월)을 바로 바꾸는 토글형 선택 컨트롤. 회색 트랙 위에 선택된 항목이 흰 칩으로 보입니다. 클라이언트 컴포넌트입니다(`"use client"`가 달려 있어 서버 컴포넌트에서 import해도 됩니다. 단 `onChange`는 클라이언트 컴포넌트에서 넘깁니다).
  - `items`(필수): `{ value, label, icon?, disabled? }[]`. 2~6개. 이름은 1~4자. `icon`은 글자 앞 아이콘(lg 20 · md·sm 16, 크기는 자동)
  - `value`·`onChange`(제어) 또는 `defaultValue`(비제어, 기본 첫 항목). 항상 하나가 선택되어 있습니다(선택 없음 상태 없음)
  - `size`: `sm`(트랙 32) · `md`(40, 기본) · `lg`(48). 글자 label-3 · label-2 · label-1. `md`·`sm`은 터치 눌림 영역 44. 구간별 객체도 받음(`{ base: "lg", desktop: "md" }`)
  - `fullWidth`: 부모 폭을 꽉 채움(기본 `false`, 가장 긴 항목 폭으로 같은 폭). 구간별 객체도 받음(`{ base: true, tablet: false }`)
  - 선택이 바뀌면 흰 칩이 옆 칸으로 미끄러짐(CSS, 움직임 줄이기 설정이면 멈춤)
  - `aria-label`을 꼭 줍니다(`radiogroup`의 이름). 키보드는 ←·→·Home·End로 선택
  - 금지: 화면 섹션 전환(Tab을 씀), 7개 이상(Select·Tab), 선택 없음 상태. 상세 규칙은 `components/segmented-control/AGENTS.md`
- **`Tab`** — 같은 화면에서 보는 내용(섹션)을 바꾸는 밑줄형 탭. 항상 하나가 선택돼 있고 선택된 탭은 굵은 글자와 아래 밑줄로 표시됩니다. 클라이언트 컴포넌트입니다(`"use client"`가 달려 있어 서버 컴포넌트에서 import해도 됩니다. 단 `onChange`는 클라이언트 컴포넌트에서 넘깁니다).
  - `items`(필수): `{ value, label, badge?, disabled? }[]`. 2~6개. 이름은 2~6자 명사. `badge`는 새 소식이 있는 탭에만(브랜드 색 점, 스크린리더는 "(새 소식)")
  - `value`·`onChange`(제어) 또는 `defaultValue`(비제어, 기본 첫 탭)
  - `size`: `lg`(막대 48) · `md`(40, 기본) · `sm`(32). 구간별 객체도 받음(`{ base: "lg", desktop: "md" }`)
  - `layout`: `fill`(기본, 탭이 폭을 똑같이 나눔. 이름이 안 들어가면 이름 폭을 지키고 가로 스크롤. 마우스는 끌어서, 놓으면 관성) · `hug`(이름 폭만큼만, 넘치면 가로 스크롤). 5개 이하는 fill, 6개이거나 이름이 길면 hug. 구간별 객체도 받음
  - `fade`: 탭이 넘칠 때 스크롤할 쪽 가장자리에 그라데이션(기본 `true`, 넘칠 때만 자동으로 나타남. 선택된 탭이 화면 밖이면 보이게 스크롤됨)
  - `aria-label`을 꼭 줍니다(`tablist`의 이름). 키보드는 ←·→·Home·End로 선택. `tabpanel` 연결(`aria-controls`)은 아직 없음
  - 금지: 탭 안에 탭, 탭으로 페이지 이동(링크·버튼을 씀), 목록 거르기(Category를 씀). 상세 규칙은 `components/tab/AGENTS.md`
- **`PageCounter`** · **`PageDots`** — 배너·캐러셀·이미지 갤러리의 현재 위치 표시(표시 전용, 누를 수 없음). 서버 컴포넌트에서도 쓸 수 있습니다.
  - 공통: `current`(현재 위치, 1부터)·`total`(전체 개수) 필수, `size`(`md` 기본 · `sm`). 스크린리더는 "10개 중 1번째"로 읽음
  - `PageCounter`: "1 / 10" 숫자. `variant`: `normal`(진한 바탕·흰 글자, 기본) · `alternative`(연한 바탕·회색 글자). 개수 제한 없음(이미지가 많은 갤러리)
  - `PageDots`: 점. 2~7개만(8개 이상이면 `PageCounter`). `variant`: `normal`(밝은 바탕, 기본) · `white`(이미지 위, 나머지 점 흰색 40%)
  - 금지: 점으로 클릭 이동 만들기, 현재 위치가 아닌 점 강조. 상세 규칙은 `components/page-indicator/AGENTS.md`
- **`Pagination`** — 많은 데이터를 페이지로 나눠 보여 줄 때의 페이지 이동(3~4화면 이내 분량이면 쓰지 않음). 서버 컴포넌트에서 쓸 수 있습니다(`"use client"` 없음).
  - `page`(현재, 1부터)·`total`(전체 페이지 수) 필수. `total <= 1`이면 그리지 않음
  - 링크: `getHref={(page) => "?page=" + page}` + Next.js는 `linkComponent={Link}`(서버 컴포넌트 그대로). 버튼: `onChange={setPage}`(클라이언트 컴포넌트)
  - `variant`: `extended`(9칸) · `compact`(7칸). 값 하나 또는 구간별 객체(`{ base: "compact", desktop: "extended" }`). 기본 `{ base: "compact", tablet: "extended" }`(768px 미만 compact). Figma는 480px 기준이지만 MINT 구간은 `tablet:`(768)·`desktop:`(1024)뿐
  - 번호 배치는 자동(처음·끝 + 현재 주변, 칸 수 고정). 현재 페이지 `aria-current="page"`, 첫·마지막의 이전·다음은 자동 비활성
  - 금지: 모바일에서 extended 고정. 상세 규칙은 `components/pagination/AGENTS.md`
